## Where the code differed from PHASE_G.md

- **Phases C to F did not exist in this checkout.** Only A and B were built: announcements were a "coming soon" placeholder, with no seed file, API, PDFs, Latest-notices block, saved items or reminders. With your go-ahead I built the Phase C public part from `docs/PHASE2.md` first: seeds (9 items, all 7 services, all 5 types, every title marked `[SAMPLE]`/`[নমুনা]`), the public list (service chips, type select, bilingual search, newest first, Load more at 10, NEW badge within 14 days), the detail page (inline PDF via `<object>`, "Download PDF" requires login), the Latest-notices block on guide pages, and the header link (already there).
- **Not built:** saved-items UI, reminders, the print view. Instead, as agreed, there is an API-level resolver, `resolveAnnouncements(ids)`, which reports unpublished or deleted items as `available: false`. Nothing in the UI calls it yet; the Saved items list (Phase E) should.
- **Seed storage:** the seeds are in `src/data/announcements.js` and are loaded into the mock db once. The sample PDF `public/announcements/sample-notice.pdf` is generated by `scripts/make-sample-pdf.mjs` and attached to one seed.
- **File names:** `src/api/announcements.js`, `src/api/mock/mockAnnouncements.js`, `fileStore.js`, `src/components/RequireAdmin.jsx` and the pages follow the existing conventions. `mockAuth.js` is where roles live (there is no `auth.js`-level role logic).
- **Guests get `FORBIDDEN`, not `UNAUTHENTICATED`,** from the admin functions in the mock, as the spec's tests require. The contract says a real server answers a guest with `401`.
- **`pdfUrl` in lists:** the mock fills it in only for static files; uploaded files get a temporary object URL from `getAnnouncement` and the admin write calls. Lists return `hasPdf`, `pdfName`, `pdfSize`. Call `releaseAnnouncement()` when done with one (the pages do).

## Decisions

- `role` is on the user record; records without one are plain users. The admin is seeded under its own flag (`seededAdmin`), so a browser that was seeded before Phase G still gets it once. `register()` and `updateProfile()` never read `role` (tested).
- Validation is shared: `utils/announcementInput.js` (form and mock), `utils/pdfValidate.js` (first bytes `%PDF-`, size, sanitised name), `utils/safeUrl.js` (http/https only). The source link is also checked at render time in the card and the detail page, and PDF URLs through `safeAssetUrl`.
- A new file is re-wrapped as `application/pdf` before it is stored; the browser-reported type is ignored.
- Replace/remove deletes the old blob only after the new state is saved. A rejected PDF changes nothing.
- Admins can open a draft by URL (draft banner on the detail page); everyone else gets the normal not-found state. Public lists, search, the guide block and `resolveAnnouncements` never include drafts.
- **Leave-without-saving:** `utils/navGuard.js` plus `useUnsavedGuard`. App.jsx undoes a hash change while a blocker is set and the form shows a dialog; the tab close or reload uses the browser's own `beforeunload` prompt. The back button is handled the same way, at the cost of one extra history entry.
- "Unpublish" in the edit form changes only the status (it does not save other edits, which stay in the form).
- After a mutation the admin list reloads page 1, so a long "Load more" list collapses back to the first page.
- The status chip on the public card appears only for drafts (admins previewing).

- `npm test`: 73 tests pass (36 earlier ones unchanged, plus announcements/admin guard/visibility/PDF/URL/CRUD/seeding/saved-item resolver/route tests). `npm run build` passes.
- Headless Edge via DevTools protocol, dev server, mock latency 30 ms: the full Definition of Done flow (admin creates a draft with a PDF; a guest cannot see it in the list, by direct URL, or in the guide block; publish; it appears in the public list and the guide block; edit; unpublish; delete with confirm; reset demo data). Guests and normal users get the login prompt / "no access" screen, and the menu link shows for admins only. Bad URL, fake PDF and oversize PDF are rejected inline, in English and Bangla strings. Leave dialog on link click and on the back button; none after a save. The delete dialog traps Tab and closes on Esc.
- Screenshots reviewed at 390 px and 1280 px, light and dark, Bangla and English, for the public list, detail, admin list (cards on mobile, table on desktop), form with errors, login, and no-access. No horizontal overflow at 390 px on the checked pages.

## Not verified

- **A real keyboard-only pass.** Tab order and the dialog trap were exercised with synthetic key events; I did not walk the form with a physical keyboard or a screen reader. The drop zone works through its "Choose file" button; drag-and-drop itself was not exercised (only the file input).
- **The inline PDF preview.** Headless Edge shows an empty grey frame for PDFs, so the viewer was not seen working; the `<object>` fallback link is untested visually.
- **IndexedDB failure paths** (private windows, quota). The store throws `STORAGE_UNAVAILABLE`; the UI shows a generic message. Note that `localStorage` writes swallow quota errors (existing `store.set`), so a very full storage could lose a document write silently.
- **Bangla copy** was written by me and should be read by a native speaker.
- Dark/light screenshots were not taken of every state (for example the open dialogs).

## Follow-up: Excel and image attachments

Requested after the first pass (the original Phase G listed image attachments as out of scope).

- **Model:** the single PDF stays as is. Each announcement also has `attachments` (up to 5): Excel (`.xlsx`, `.xls`) and images (`.png`, `.jpg`/`.jpeg`, `.gif`, `.webp`). Each file is checked by its first bytes against its extension (`utils/attachmentValidate.js`); the browser MIME type is ignored. SVG, macro workbooks (`.xlsm`, `.xlsb`) and CSV are rejected on purpose. Same size limit as the PDF (`VITE_MAX_PDF_MB`, default 5 MB; the name is historical).
- **API:** `createAnnouncement(input, pdf, { attachments })` and `updateAnnouncement(id, patch, pdf, { removePdf, addAttachments, removeAttachmentIds })`. Everything is validated before anything is stored; delete, reset and remove drop the blobs. Lists return attachments without `url`; `getAnnouncement` and the admin write calls return temporary object URLs. A draft's attachments are as unreachable as its PDF.
- **UI:** an "Other attachments" field in the form (thumbnails for images, count and limit hint, remove/undo), an attachment count on cards, and an Attachments section on the detail page (images shown inline, Excel as download rows; downloads need login, as for the PDF).
- **Verified:** 79 tests pass; in headless Edge a fake `.png` is rejected inline, a PNG and an `.xlsx` attach, publish, appear for a guest (image inline, download gated), and the list card shows the count.
- **Not verified:** the `.xlsx` check is only the zip signature, so a zip renamed to `.xlsx` passes in the mock; the real server must open it. Excel files cannot be previewed in the browser. The Bangla copy for the new strings needs a native read.
